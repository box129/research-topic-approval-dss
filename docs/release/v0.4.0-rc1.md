# v0.4.0-rc1 Release Candidate Notes

Recommended tag after PR #107 is reviewed, merged to `main`, and the final clean release gate passes:

```text
v0.4.0-rc1
```

Do not create this tag from the PR branch.

## Release Classification

`v0.4.0-rc1` is a controlled release candidate. It is suitable for local development and validated integrated demonstration. It is not a final stable production release and does not prove public HTTPS production readiness.

## Included Capabilities

- React/Vite role-based frontend workflows for student, lecturer, and admin users.
- Node/Express backend with cookie-based authentication and role protection.
- PostgreSQL/Prisma schema and migrations through notification foundation.
- Public and authenticated topic similarity flows.
- Approved similarity-scoring contract:
  - Jaccard `0.20`
  - TF-IDF `0.30`
  - SBERT `0.50`
  - fallback `0.40 / 0.60`
  - LOW below `0.40`
  - MEDIUM from `0.40` to below `0.70`
  - HIGH at or above `0.70`
  - Tier 1 minimum `0.10`
  - Tier 2/3 combined minimum `0.60` and real SBERT minimum `0.60`
- Admin governance APIs, audit logging, users/settings/topics/reports dashboard surfaces.
- Admin topic import preview/commit UI using admin-protected endpoints.
- Lecturer decision history and read-only research trend aggregates.
- Email provider-mode foundation with mock disabled in production.
- Notification backend foundation.
- Reproducible evaluation and data-quality scripts.
- Deployment runbooks, readiness endpoint, CI workflow, and release gate automation.

## Upgrade from Previous UI RC

1. Pull the merged `main` commit.
2. Install dependencies with `npm ci` in `backend/` and `frontend/`.
3. Apply migrations with `npx prisma migrate deploy`.
4. Start SBERT, backend, and frontend/static host in the documented order.
5. Verify `/api/v1/health`, `/api/v1/readiness`, and SBERT `/health`.
6. Run `npm run release:check` from repo root.

## Known Limitations

- Pilot evaluation labels are manually constructed.
- Final lecturer-reviewed effectiveness benchmark is missing.
- Departmental-scale data-quality validation is unverified.
- Real SMTP transport delivery remains deferred.
- Notification event hooks and notification frontend UI remain deferred.
- Lecturer supervisee assignment workflow remains deferred.
- Admin report exports remain deferred.
- Audit export/purge/delete policy remains deferred.
- Monitoring and alerting depend on the target deployment environment.
- Full-stack Docker/Compose deployment is not provided.
- Public production deployment is not proven by local tests.

## Post-Merge Release Steps

After PR #107 is merged:

1. Synchronize local `main`.
2. Confirm a clean tracked worktree.
3. Run the final release gate from merged `main`.
4. Create the annotated RC tag:

   ```powershell
   git tag -a v0.4.0-rc1 -m "v0.4.0-rc1"
   ```

5. Push the tag.
6. Create a GitHub pre-release using these notes.
7. Do not mark it as a stable production release.
