# Institutional Evidence Workflow Component Map

## How to use this map

This map records the current component evidence and the intended responsibility under **Institutional Evidence Workflow**. “Behavior” includes API use, payloads, state transitions, accessible names, test IDs, route integration, and business constraints. “Presentation” includes layout, spacing, typography, surface, and responsive treatment. Page components remain orchestration boundaries and must not be casually replaced.

Classifications are:

- **Retain unchanged initially** — preserve behavior and presentation until a scoped design proves a need.
- **Restyle through tokens** — preserve structure and behavior; centralize visual changes.
- **Consolidate** — merge duplicate concepts behind a compatible shared primitive.
- **Refactor structurally** — preserve behavior while changing composition or responsive structure.
- **Replace only after behavior parity is proven** — high-risk behavior requires explicit parity evidence before replacement.

## Replacement safeguards

Do not casually replace `TopicForm`, `ResultsDisplay`, `ConfirmActionModal`, `ProtectedRoute`, authentication state, API helpers, or high-impact page orchestrators. Any replacement must enumerate current consumers, map every tested behavior, preserve accessible names and test IDs or provide an approved migration, pass focused and full tests, and produce approved desktop/mobile evidence.
