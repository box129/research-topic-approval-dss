# Free Managed Staging Deployment Prep

## Status

PR #121 prepares provider-specific guidance for a free managed staging deployment of the Research Topic Approval DSS. It does not execute deployment, verify provider uptime, add real provider URLs, or prove public production readiness.

Target FYP/demo topology:

| Component | Provider |
| --- | --- |
| Frontend | Vercel |
| Backend | Render Free web service |
| Database | Neon Free PostgreSQL |
| SBERT service | Hugging Face Spaces |
| Email | `EMAIL_PROVIDER=disabled` initially |

Use this plan with [free-managed-staging-plan.md](./free-managed-staging-plan.md) and [staging-deployment-evidence-template.md](./staging-deployment-evidence-template.md).

## Deployment Objective

Prepare a no-cost staging/demo deployment path that can show the real application without committing secrets, fake readiness, or real student records.

The deployment should prove:

- Vercel serves the frontend build.
- Vercel routes frontend `/api/*` traffic to the Render backend, or an approved equivalent proxy exists.
- Render runs the backend with production-safe environment values.
- Render connects to Neon through `DATABASE_URL`.
- Render connects to the Hugging Face SBERT Space through `SBERT_SERVICE_URL`.
- Neon has committed Prisma migrations applied.
- Hugging Face Spaces exposes SBERT `/health`.
- Email remains disabled until SMTP provider smoke credentials exist.

## Recommended Setup Order

1. Create the Neon PostgreSQL project.
2. Create the Hugging Face SBERT Space and confirm `/health`.
3. Create the Render backend service and set environment variables.
4. Run Prisma migrations against Neon.
5. Create the Vercel frontend project.
6. Configure Vercel `/api` routing to the Render backend.
7. Capture health/readiness/frontend evidence.

## Required Cross-Service Values

Use placeholders in notes and evidence. Do not commit real values.

| Value | Source | Used by |
| --- | --- | --- |
| Neon connection string | Neon dashboard | Render `DATABASE_URL` |
| Render backend URL | Render service page | Vercel `/api` rewrite/proxy, `FRONTEND_URL`/`CORS_ORIGIN` decisions |
| Hugging Face Space URL | Hugging Face Space page | Render `SBERT_SERVICE_URL` |
| Vercel frontend URL | Vercel project page | Render `FRONTEND_URL` and optionally `CORS_ORIGIN` |
| Strong JWT secret | generated by operator | Render `JWT_SECRET` |

## Frontend API Routing Note

The current frontend API client uses relative `/api/v1` requests. It does not currently read `VITE_API_URL`.

For Vercel staging, the frontend should point to the backend by routing:

```text
https://<vercel-demo-origin>/api/*
```

to:

```text
https://<render-backend-origin>/api/*
```

Do not commit a real Render URL in this repository. If Vercel requires a committed `vercel.json` for rewrites, add it only in a later reviewed config PR or a deployment-specific branch after the Render URL is known. Until then, record this as a deployment setup requirement, not a completed proof.

## Email Boundary

Set:

```text
EMAIL_PROVIDER=disabled
```

for the first free staging deployment.

Reason:

- password reset email should not use mock mode in production-like staging
- SMTP credentials may not exist for the FYP demo
- free staging should not accidentally send real mail
- SMTP provider smoke already has a separate workflow through `npm run smoke:smtp`

Only switch to `EMAIL_PROVIDER=smtp` after deployment-owned SMTP credentials and a controlled recipient are available.

## Evidence To Capture

Capture:

- commit hash
- provider names only
- migration status result
- Render backend health result
- Render backend readiness result
- Hugging Face SBERT health result
- Vercel frontend HTTP result
- `/api` proxy result from the Vercel origin
- SMTP status: `DISABLED` or smoke result
- free-tier limitations encountered
- pass/fail conclusion

Do not capture:

- `DATABASE_URL`
- Neon passwords
- JWT secrets
- provider API tokens
- SMTP credentials
- real student records
- private reset links
- raw database dumps

## Pass / Fail Checklist

Pass for FYP/demo when:

- Neon database is reachable from Render.
- Prisma migrations deploy cleanly.
- Hugging Face SBERT `/health` succeeds after warmup.
- Render `/api/v1/health` succeeds.
- Render `/api/v1/readiness` is `ready`, or any degraded state is explicitly explained.
- Vercel frontend loads.
- Vercel `/api` routing reaches Render.
- `EMAIL_PROVIDER=disabled` is intentional and documented.
- no secrets or real student data are committed.

Fail when:

- migrations fail
- backend cannot reach Neon
- backend cannot reach SBERT and semantic readiness is claimed anyway
- frontend loads but API calls cannot reach Render
- mock email mode is used in staging
- evidence contains secrets or real student data
- fake records, fake results, or fake provider proof are used

## Expected Free-Tier Limitations

Expect:

- Render cold starts or sleeping behavior
- Vercel build/deployment usage limits
- Neon storage and compute limits
- Hugging Face Space startup delay
- slow first SBERT request
- limited logs and retention
- no production uptime guarantee
- provider-specific bandwidth/request limits

These limitations are acceptable for FYP demonstration if documented. They are not acceptable as proof of dependable departmental production.

## Troubleshooting Summary

| Symptom | Likely cause | Check |
| --- | --- | --- |
| Vercel frontend loads but data requests fail | `/api` rewrite/proxy missing or wrong | Test `<vercel-origin>/api/v1/health` |
| Render refuses production startup | weak `JWT_SECRET`, missing origin, or mock email | Check Render env values |
| Backend readiness is `not_ready` | Neon URL wrong or migrations missing | Run Prisma migrate status against Neon |
| Backend readiness is `degraded` | SBERT Space sleeping, slow, or wrong URL | Check Hugging Face `/health` |
| Password reset does not email | `EMAIL_PROVIDER=disabled` | Expected for first staging path |
| Cookies do not persist | CORS/origin/proxy mismatch | Verify `FRONTEND_URL`, `CORS_ORIGIN`, and HTTPS origins |

## Current Boundary

This PR prepares deployment guidance only. Free managed staging remains unproven until Vercel, Render, Neon, and Hugging Face are configured and evidence is captured safely.
